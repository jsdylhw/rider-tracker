# 国内路线约束与偏好

国内单日路线由 Agent 把自然语言转换成有序途经点、强约束和软偏好，再由高德骑行接口返回真实道路方案。系统请求每个固定路段最多三条高德备选，多途经点使用有界组合，避免候选数量随路段数指数增长。组合裁剪会结合剩余路段的最小、最大距离，保留仍可能达到目标距离的部分路线。

处理顺序如下：

1. 保持用户明确给出的途经点及顺序。
2. 请求高德骑行备选和 `cost,navi,polyline` 字段。
3. 标准化总距离、总耗时、道路名称、导航动作、道路类型和轨迹。
4. 淘汰违反重复道路、掉头、轮渡、阶梯或绕行上限的候选。
5. 根据最短、最快、少左转、少右转、少拐弯、简单导航、少隧道和少桥等偏好排序。
6. 将实际质量证据写入 `route_quality`，供 Agent 和前端展示。

## 强约束

`route_constraints` 表示能够根据地图结果确定性验证的要求：

- `avoid_repeated_roads` 与 `maximum_self_overlap_ratio`
- `avoid_u_turns`
- `avoid_ferry`
- `avoid_stairs`
- `maximum_detour_ratio`

绕行比例以相同有序途经点下各段最短高德备选之和为基准。它不用于判断用户主动指定的途经点是否必要，也不用于把环线和起终点直达路线比较。

## 软偏好

`route_preferences` 用于排序通过强约束的高德备选：

- `routing_priority`: `balanced`、`shortest`、`fastest`
- `turn_bias`: `neutral`、`fewer_left`、`fewer_right`、`fewer_turns`
- `navigation_complexity`: `neutral`、`simple`
- `prefer_fewer_tunnels`
- `prefer_fewer_bridges`

软偏好不构成通行或安全保证。高德没有返回导航步骤时，转向与特殊通道证据标记为不可用，系统不得声称已经满足少转弯要求。

同一组途经点下，距离和耗时以该组高德备选中的最短值为基线。不同途经点骨架之间，则使用所有候选共同的最短距离和最短耗时作为比较基线，避免“最快”候选因为各自相对耗时都为零而选中实际更慢的路线。用户给出目标距离时，目标距离偏差仍优先于软偏好。

## 当前边界

高德骑行结果不提供足够稳定的自行车道、路面质量、照明、实时车流、红绿灯或海拔证据。因此“自行车道多”“路面好”“夜骑安全”“少机动车”“平路”和坡度上限目前不能作为已验证约束。沿河、公园、补给和厕所等需求仍由途经点骨架表达；以后可以通过沿线 POI 检索增加独立评分。
