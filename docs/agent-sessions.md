# Agent 会话管理

主 Agent 窗口和 AI 路线页通过紧凑工具栏提供会话列表、切换、新建、删除和刷新；正常状态隐藏提示行，加载或失败时显示。浏览器 localStorage 只保存当前会话 ID，
Python SQLite 同时保存模型上下文、公开对话记录和请求去重缓存。恢复记录失败时禁用发送，并显示重试入口，
避免空白界面继续使用隐藏的历史上下文。浏览器记住的会话已删除时，自动使用新 ID 开启空会话。

## 数据与 API

- 数据库版本 13：原 `chat_sessions` 保存上下文和请求缓存；新增 `chat_session_views` 保存分类、标题、时间和完整公开轮次。
- 公开响应为 `agent_session.v1` / `agent_session_list.v1`，不公开原始模型消息、工具结果或活动文件路径。
- Python：`GET/POST /api/chat-sessions`，`GET/DELETE /api/chat-sessions/{session_id}`。
- Browser/BFF：对应 `/api/agent/sessions`。会话管理使用已有 API 鉴权，不依赖模型或地图配置。
- `kind=chat|route_plan` 分开列出两个入口的会话。标题使用首条用户消息。请求重放不重复添加聊天记录。
- 内存 TTL 不再删除持久会话；公开记录不跟随最近 100 次请求去重缓存一起淘汰。
- 旧会话按可用请求缓存/文本上下文恢复，明确提示旧记录可能不完整；不会宣称找回已经丢失的历史。

## 上下文和操作边界

新建使用独立 ID，不继承活动选择、路线引用或模型历史。切换路线会话恢复其已选草稿；新建路线会话清除旧草稿及
旧 AI 地图预览，后续消息走 create。主窗口历史路线卡片仍带原会话 ID 和版本，打开时恢复对应对话。

请求处理中不能通过会话控件切换或删除；后端也拒绝删除正在执行的会话。删除清理聊天上下文、公开记录和去重缓存，
留下会话 ID 的删除标记，避免迟到写入重新创建已删除会话。已保存路线、活动和后台任务不随聊天删除。

本轮不调整 `loop_engine.py`、模型工具选择或 Route Agent 的历史压缩策略。会话隔离解决界面与后端上下文不一致，
不能替代后续对子 Agent 未调用工具的修复。

## 验证基准

会话专项覆盖：重启恢复、TTL 后恢复、超过去重缓存长度的公开记录、重复请求不重复显示、删除后拒绝迟到写入、
处理中删除冲突、API 鉴权、Browser/BFF CRUD、恢复失败禁用发送、新建后上下文隔离、路线会话切换后不误改旧草稿。

使用隔离临时数据库和确定性 API 替身测试持久化与 UI 边界；这些验证不代表真实模型或地图质量验收。

## 2026-09-22 会话删除和历史候选修复

- 新对话及删除最后一个会话后的空白页使用本地会话 ID，首次发送消息时才由后端持久化，避免打开页面或删除操作反复生成“新规划”。删除后优先打开同入口剩余会话。
- 删除采用原生 `dialog` 配合应用样式，明确取消/删除，默认聚焦取消，支持 Esc。删除绑定弹窗打开时的会话 ID；恢复失败不再禁用删除，404 按已删除处理，其他错误保留提示。
- 历史路线加载中生成的候选按钮原先保留 disabled 状态；现在会话 busy 状态变化会重新渲染候选按钮，恢复后可预览或确认。
- JavaScript 448 项测试通过，涵盖确认/取消、恢复后按钮解锁、恢复失败会话删除及删除后不持久化新空会话。未直接清理用户历史数据，未进行浏览器视觉验收。
