## 2026-09-28 失败诊断与输出预算补验
用户反馈的两次任务均停在 composing_cards，耗时约 50 秒；持久化结果只有 narration_failed，原 handler 捕获后未记录异常类型，通用 Worker 对 JobExecutionFailed 也没有终态日志，因此无法追溯原始原因。NumExpr 的线程提示不是失败证据。

使用同一任务输入真实重测：原 8000 token 预算下生成 32 张卡片，使用 7685 输出 token，证明本次可成功但预算余量较小，不能据此断言原失败一定是截断。现按样本数与最大卡片数扩大有界预算（8000–24000），仍只有一次模型调用；明确拒绝 stop_reason=max_tokens 的不完整结果。Worker 记录 job_id、失败阶段、异常类型，不输出原始异常/模型内容；专用结果分别提示模型请求失败、输出截断，其余保留通用失败。

修改后同一输入经真实 Places/模型、临时 JobStore、Worker 保存和结果查询验证成功：模型提交 33 张，校验后保留 32 张，任务 succeeded。没有改写原任务或用户路线；临时数据库已清理。讲解测试 22 项、Worker/任务/架构测试 44 项通过。真实重测成功不代表所有网络或模型响应都稳定成功，旧任务的原始异常仍不可恢复。
