# FIT 工具材料表达与输出预算对照（2026-09-21）

## 范围与方法

使用同一条真实 FIT 的 0–300s 闭区间，5 秒分桶，共55个有记录的桶。真实调用当前配置的 deepseek-v4-flash，thinking=enabled、reasoning_effort=low、temperature=0.3；未改生产配置或业务实现。只做只读统计与模型请求，没有下载、上传。

对三种格式传递完全相同的10列：起止、样本数、功率/心率均值、功率有效/缺失/零值数、心率有效/缺失数。对照格式为列式数组 columns、列名+二维行数组 table、逐桶对象 objects。另测完整现有列式结果 full_columns 和只给窗口汇总 summary_only。

为了自动核对数值，要求严格 JSON：7项整窗统计，明细任务另要求55行×10列，逐值与工具输出比较。1200、4096和8192是最大输出预算，不是固定输出长度；推理保持当前配置。没有复用原700字自然语言限制，所以这是材料/预算的受控对照，不是原对话全文复现，也不能据此认定之前零值72错误的唯一原因。

三种格式的明细输出都要求二维表，对 table 输入存在复制形式一致的便利；这正适合“展示逐桶明细”任务，不代表它在所有语义分析任务都更优。

## 结果

- 汇总任务：三种相关字段格式、完整列式结果、summary_only，5次均数值正确。首个 columns 输出直接返回7字段而非嵌套 summary，初始脚本误判；人工核对后修正为数值通过。
- 明细任务：1200/4096预算的6次全部以 max_tokens 截断。不能把不完整 JSON 当成计算错误。
- 8192预算各跑两次：table 2/2逐值正确，objects 2/2逐值正确，columns 1/2正确，另一次达到8192后截断。样本量很小，不构成可靠成功率估计。
- 所有完整的明细回答均与工具55行×10列一致；没有观察到完整回答中的数值错误。
- 当前启用推理；columns 的一次4096请求正文为空、但输出token已耗尽，因此输出预算不能只按可见表格字数估计。没有分别记录推理token，不能精确归因其消耗比例。

## 建议

1. 保留列式紧凑表示作为内部格式，不换成重复字段的逐桶对象。
2. 按任务选择结果：只问均值给 window_summary；看走势/逐桶明细再附请求相关字段的 series。字段筛选必须保留相关计数和 null，不能重现之前删除 samples 的问题。
3. 模型需要读逐桶明细时，可在展示适配层转换为 columns+rows；无需改变底层统计或持久化结构。这次二维表和列式数组的逻辑输入几乎相同（明细1951 vs1948），逐桶对象为4593。
4. 预算按输出需求分级：简短汇总1200足够本次样本；完整55行明细需要更高预算。检测 stop_reason=max_tokens，不能把截断当成完整结果。更长窗口考虑界面直接显示工具表格，模型只写解释，而非无限增加预算。
5. 摘要任务输入：full_columns 7241 → 相关列 columns 1875 → summary_only 272。主要节省来自减少不相关材料，非缩短字段名或牺牲统计证据。

本轮仅记录结果，未修改生产格式、输出预算或提示词；不把两次样本耗时当作普遍性能结论。

原始探针与回答保存在 /tmp/fit-format-ab/、/tmp/fit-format-ab-repeat/，脚本 /tmp/fit_format_ab.py、/tmp/fit_format_ab_more.py、/tmp/fit_format_ab_repeat.py。临时文件可能清理；报告不包含账号凭证或活动身份。


## 后续实施：按问题投影与预算调整

用户确认后已在 FIT 工具适配层实现 `view=summary/intervals` 和可选 `metrics`。底层计算仍返回列式数组；模型请求明细时得到 `columns+rows`，请求汇总时不带明细。字段按指标组筛选，保留有效/缺失/零值统计与 null。省略 metrics 保留全部指标，省略 view 默认明细，兼容原工具调用参数。

FIT 查询输出上限由1200提高到8192；移除与完整明细冲突的700字限制。响应 stop_reason=max_tokens 时，在接受文本或 submit_query_answer 前报错，不静默展示截断结果。暂不增加自动重试或修改全局模型配置。


实施后验证：162项定向测试通过，compileall 与 diff --check 通过。真实 FIT 子 Agent 两轮验证（`/tmp/fit_window_projection_check.jsonl`）：

- 只问汇总：模型正确选择 summary + power/heart_rate，不带明细，3.80秒，回答99.0 W、130.9 bpm、功率缺失1/零值70。
- 要求每5秒明细：模型正确选择 intervals + power/heart_rate，得到55行二维表，随后又查询一次summary，10.08秒；整窗统计正确，未发生截断。
- 以上只确认格式选择、主要汇总及完整返回；没有把整段自然语言逐句判为通过。明细回答仍出现自行概括记录空档、桶样本数、计算百分比等内容，不应据此推断所有解释均准确；还存在一次重复summary取数。此轮不扩展自动答案校验或恢复机制。
