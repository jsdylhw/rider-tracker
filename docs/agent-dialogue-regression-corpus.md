# Agent 多业务对话回归语料

基线：`develop / 1f9e74b`。来源：[历史能力验收](agent-capability-audit.md)、[FIT 格式验证](fit-query-format-validation.md)以及当前工具契约。以下是可复用输入和验收条件，不是本轮真实模型测试结果。部分历史记录只保留了请求简写，这里按原业务意图整理，不宣称逐字复原。

## 使用方式与证据范围

- 每组从独立空会话开始，组内按顺序发送；不要把“这条”“这些”“刚才”拆成独立单轮。
- 默认用独立测试数据库、生成的 FIT 和 Provider 替身；真实账号下载/上传必须单独确认目标与执行范围，不能由语料文件自动授权。
- 页面入口为 `/api/agent/chat`（可请求 NDJSON）；这是当前 Python Web → 私有 Agent 进程入口。旧记录直接使用 `/api/chat`，不等于已验证现在的完整入口。
- 保存每轮 request/session ID、状态、工具名与关键参数、业务目标 ID、结构化结果、终态事件、耗时及 token。公开报告用别名，原始回答只留本地隔离产物，避免提交 FIT、位置轨迹、账号和 Token。
- 对比业务事实及参数，允许合理的定位/澄清步骤和措辞变化。不得仅凭顶层 completed 或模型“已成功”判通过。
- 每个结果标记：隔离通过 / 真实模型与替身工具通过 / 真实业务通过 / 失败 / 未执行。重要自然语言场景建议重复 3 次，逐次保留失败，不能以最后一次成功覆盖。

## 固定材料约定

使用 A（较早骑行）、B（最新骑行）、C（其他运动类型）三个测试活动别名。A/B 有可解析 FIT，至少一个活动缺失 average_speed。另准备空库与已有上传证据的活动 P；外部 ID 必须是替身记录或经核对的测试活动，不使用硬编码个人 ID。

FIT 数值基准使用生成数据：elapsed_s 为 0、5、10、300、305；power 为 100、0、缺失、200、999；heart_rate 为 100、110、120、缺失、199。闭区间 0–300s 的功率均值为 100 W（有效 3、零值 1、缺失 1），心率均值为 110 bpm（有效 3、零值 0、缺失 1）。305s 不计入。真实 FIT 复测须重新从该文件计算基准，不能套用历史报告中的 99.0 W/130.9 bpm。

## 多轮业务脚本

| ID | 前置条件与依次发送的文本 | 必须核对的结果 |
| --- | --- | --- |
| D01 普通聊天与空库 | 空库：①“你好，先聊聊。” ②“列出最近 3 条骑行的时间、距离和时长，不生成报告。” | 聊天无需领域工具；查询调用活动定位工具，明确空结果，不编造活动或触发同步 |
| D02 列表与选择 | A/B/C：①“列出最近 3 条活动，不生成报告。” ②“看列表里的第二条。” ③“分析这条，简短总结，说明数据不足。” | 第二条以实际列表顺序绑定，分析使用同一目标；不能自行切到最新活动 |
| D03 指定指标比较 | 至少两条骑行：①“列出最近 3 条骑行。” ②“比较这些活动的距离、时长、平均速度，缺少不要猜。” | compare_activities.metrics 包含 distance/duration/average_speed；缺均速明确无数据，不以距离/时间补算；不要求模型逐字复现模板 |
| D04 FIT 自然语言与分桶 | 先选择生成 FIT：①“看这条前五分钟的平均功率和平均心率，只用原始 FIT。” ②“改为 0–5 分钟，每 5 秒查看功率和心率，另给整窗均值。” ③“改为每 10 秒，保留整个窗口的汇总。” | 都经 query_activity_detail → FIT 工具；窗口 0–300s；summary/intervals 按需投影；整窗均值不随 5s/10s 变化；零值、缺失分开，缺失列不消失；模型逐桶叙述另外核对 |
| D05 训练建议 | 已选多条骑行：①“根据这些活动给下次轻松训练建议及依据，不规划路线。” | 使用当前数据形成建议并说明缺失；不启动地图/发布；建议文字质量人工评估，不以工具返回成功代替 |
| D06 报告工作流 | A/B 有报告：①“本地最近 2 条创建可恢复工作流，确保报告再汇总，不上传，已有报告复用。” ②“查看刚才工作流，哪些完成、哪些失败？” | run_activity_workflow 使用 recent、limit=2；只包含报告/汇总目标；第二轮 get_activity_workflow 指向同一 workflow_id；报告复用，不产生发布 |
| D07 选中目标发布 | Provider 替身：①“选中较早的活动 A。” ②“上传这条到 Strava，不强制上传。” ③“再上传本地最新 1 条，不强制上传。” | 第二轮 scope=selected，发布目标 A；第三轮 recent/limit=1，目标 B；核对工作流冻结的目标及 Provider 实际收到的 FIT，不能仅看对话焦点 |
| D08 已发布与幂等 | 已有上传证据的 P：①“上传活动 P 到 Strava，已上传直接跳过，不更新描述。” ②“再上传这条，仍然不强制上传。” | 两轮复用已有外部活动 ID，无新上传/描述更新；“跳过”不能误报为本次新发布 |
| D09 Garmin 范围 | 默认 Provider 替身：①“从 Garmin 同步最近 1 条，只下载，不分析、不上传。” ②“查看刚同步的活动类型、时间、距离、时长。” | sync_garmin_activities.count=1；实际 downloaded/skipped/failed 与措辞一致；第二轮对应真实同步结果，失败时不编造新活动 |
| D10 路线委派与连续修改 | ①“法国尼斯周边约 30 km 海景环线，允许周边城镇，虚拟观景。” ②成功选中候选后：“改成 40 km，保留海景偏好。” | 主 Agent 使用 run_route_agent；独立路线入口使用 route_plan 模式；产物/版本/候选与修改目标一致。拒绝/澄清必须如实展示；不能把旧 create_route_plan 主工具期望作为当前基准，也不能保证固定三条候选 |
| D11 跨业务与会话 | 完成 D02：①“你好。” ②刷新页面或重启服务恢复该会话 ③“查看刚才选中的活动。” ④新开会话：“上传这条。” | 恢复后选择/消息与原会话一致；新会话没有目标时澄清，不借用其他会话选择或发布 |
| D12 失败恢复观察 | Provider 注入失败：①“同步最近 1 条。” ②“你好。” ③“重试。”；另组令工作流 partial 后问“重试” | 记录实际可重试动作及 workflow_id，保留为已知限制观察项：短重试与持久工作流、跨闲聊恢复未承诺修复；不能把底层显式 retry 成功当作对话重试通过 |

## 故障注入基准

| ID | 注入方式 | 预期边界 |
| --- | --- | --- |
| F01 无执行证据 | 发布/同步 Skill 激活后，模型只回复“已完成” | action_not_executed；只定位活动或沿用旧轮 trace 也不能证明本轮执行。尚未激活 Skill 的任意成功宣称不在现有强约束覆盖范围 |
| F02 输出截断 | FIT 子 Agent 返回 stop_reason=max_tokens | 返回错误，不把截断回答当完整分析；不增加自动业务重放 |
| F03 私有进程断连 | 请求发送后断开私有 Agent 传输 | 返回明确错误；NDJSON 仅一个终态；不得透明重试可能有副作用的请求 |
| F04 会话迟到结果 | 等待响应时切换会话/新开 | 旧响应不写入新会话的消息、焦点或进度；新会话隔离 |

## 可直接运行的单轮入口语料

[`dialogue-baseline-skills.jsonl`](../services/training-agent/evaluation/cases/dialogue-baseline-skills.jsonl) 复用既有 agent_eval_case.v1，共 10 条。只评估首轮 Skill 选择，不执行领域工具、不验证数据库/FIT/上传，也不替代上面的多轮脚本。

从 `services/training-agent` 执行：

```bash
python -m evaluation.cli list-cases --cases evaluation/cases/dialogue-baseline-skills.jsonl
# 以下会调用真实模型；业务工具不会执行。
python -m evaluation.cli run --cases evaluation/cases/dialogue-baseline-skills.jsonl --mode skill --repeats 3
```

现有 runner 每个 case 新建上下文，不支持把本文件多轮脚本当作有状态套件直接跑。旧 live 模式也使用 Sandbox，名称不代表真实 Provider；其默认固定问答不能用于 FIT 数值验收。后续若补自动多轮执行器，应保留本文的会话连续性、任务目标、外部副作用与结果证据检查，不只拼接提示词。
