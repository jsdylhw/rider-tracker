# 路线规划错误恢复

## 当前切片：同次规划复用成功地点

一次规划仍同步完成，不引入 Worker。模型提交骨架后，地图服务逐候选执行；每条候选独立记录业务拒绝或 Provider 失败，保留成功候选，不自动补算。

Google 地点解析成功后，在当前 `create_single_day_plan` 调用内共享结果。缓存键包括国家、原始查询、起点坐标和搜索偏置半径；起点不同不能复用。读取与写入均复制数据，避免候选之间修改共享对象。

只缓存通过地点校验的成功结果。连接失败、无结果和越界地点不缓存；后续候选可以再次请求。缓存不落盘，不跨规划调用，也不随应用重启保留。正式 Places/Routes 的有限重试继续保留。

入口：`services/training-agent/services/route/single_day.py`。
回归：`services/training-agent/tests/test_single_day_route_plan.py`，覆盖成功复用、失败后重查、不同起点隔离与对象修改隔离。

用户重试目前仍重放整个工具调用，可能重复成功候选的 Routes 请求。若继续优化，应保存本次骨架和分阶段结果，仅恢复失败候选；Provider 错误不再要求模型重新生成骨架。需要同时确定记录生命周期、业务参数变化后的失效规则与总请求时间预算，不能把本次内存缓存当成完整恢复机制。
