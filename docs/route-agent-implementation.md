# Route Agent 结构整改交付记录

本项收敛 Agent 调用、任务状态和跨入口草稿接续，不属于 Python 目录迁移，不修改冻结架构或迁移 ADR。

## 当前调用链

```text
主对话 → Main Agent → activate_skill(plan-routes) → run_route_agent
                                                        ↓
AI 路线页面 → Node BFF → Python /api/chat → RouteTaskInput → Route Agent
                                                        ↓
                         搜索资料 → 材料准备/本地组合 → 创建/修改 → Provider / Repository
```

主对话 Skill 只授权委派工具。Route Agent 不递归调用 Main Agent，不使用 Worker。
普通主对话每轮选择 Skill；前端关键词截流和后端沿用历史路线 Skill 的路径已移除。

## 已完成的结构边界

| 边界 | 当前行为 |
| --- | --- |
| 任务契约 | `route_task_input.v1`；workspace/request ID 由服务端提供，plan ID 与 revision 成对校验 |
| 结果契约 | 原 `agent_turn.v1`、`route_plan_view.v1` 增加 `route_task.v1` 摘要；只有本轮真实计划投影才算成功 |
| Context 隔离 | 子级仅使用独立 route_messages，不继承活动选择、主历史或父级工具权限 |
| 更新目标 | 模型不能覆盖服务端绑定的计划与版本；外部工作区或过期引用在模型执行前拒绝 |
| 新任务失败 | 清空旧任务引用，保留新任务对话；旧预览不能被误用作后续修改目标 |
| 服务端选项 | 创建和更新均以任务 include_elevation 为准，覆盖模型输入 |
| 失败出口 | 澄清、业务拒绝、Provider 失败和模型失败分别投影；失败不能携带旧草稿冒充成功 |
| 父级结束 | 完成、澄清和失败均终结委派回合，不重复委派或重放底层路线失败动作 |
| 页面命令 | 预览、反转、撤销、最终确认继续使用确定性命令，不由模型自动确认 |

`action_executed` 只代表进入业务工具，不代表成功。refine 可以修改，也可在区域实质变化时另建。

## 工具继续与终止规则

- action=create/update/refine 分别授权创建、更新或两者，均允许澄清、搜索及材料准备。
- `search_cycling_routes` 为中间步骤：结果交回模型，最多两次，每次最多两个查询。
- `prepare_route_materials` 为中间步骤，每回合最多两次，不满足业务完成条件。
- 搜索/准备与基于结果的规划不能在同一模型响应中执行；被阻止的同批后续调用不会执行。
- 创建/更新工具或澄清返回后终止。其他越权调用终止并保留诊断。
- 搜索次数超限为可反馈限制；总模型步数仍有上限。搜索本身不满足业务完成条件。

## 跨入口接续

主对话成功卡片捕获来源 session_id、plan_id、revision。打开草稿使用只读 get，并验证 expected_revision；
get 不修改后端 route_reference，即使响应迟到或被页面丢弃也不会切换目标。
页面后续操作使用原来源会话，不合并任意工作区。草稿进入 agentRouteDraft，地图与候选同步。
主对话清空不改变已打开草稿的来源；确定性修改只刷新同 plan_id 的当前任务版本。
并发修改由 expected_revision 拒绝，打开草稿不等于确认保存。

## 搜索实现与范围

Tavily 配置使用 `tavily.api_key`，兼容 `Tavily.api_key`。Tool 只适配参数；
`integrations/web_search.py` 请求 Provider，`services/route/research.py` 负责校验、去重和内容限额。
查询结果按排名交替选取，最多五条；每条正文最多 4500 字符，另保留最多 2000 字符检索摘要。
同一个 Route Agent 提取具体桥梁、入口/出口、道路顺序；工具内部不增加总结模型。
网页是外部参考资料，不能改变工具权限，网页距离不等于地图距离。

计划和视图的可选 `research_sources` 保存实际检索的来源元数据，不保存整篇正文。
页面标记为“规划时检索的参考资料（未逐条验证）”，不承诺每条来源均被采用。

## 2026-09-18：材料与本地骨架准备

第一、二步已接入独立 Route Agent 的非终结工具 `prepare_route_materials`：

1. `route_materials.v1` 区分地点、必经标记、有序走廊、起终点、环线和目标距离。
   来源只能引用本轮搜索 ID；不接受模型提供 GPS。走廊是有序控制点语义，不等于已验证道路几何。
2. 服务端独立解析地点，保留 Place ID、原生坐标和 WGS84 坐标；同次准备复用成功解析。
3. 围绕起点按目标距离设置有界 Strava 搜索范围，最多读取十条详情；不可用、无匹配或部分
   详情失败都返回状态，地点骨架继续生成。20 秒调度预算、单请求 4 秒 socket timeout、无重试；
   该预算不是网络总墙钟硬截止。仅使用真实详情几何，不用 Explorer 端点虚构路段。
4. 有界本地搜索保留必经点顺序和走廊控制点顺序，保留最多三个地点骨架，以及最多三个插入
   一至两条 Strava 路段的混合骨架。不反转路段来推定反向合法，不枚举全部十条路段的排列。
5. `route_preparation.v1` 明确 `validation_status=pending`；距离是路段几何长度加直线连接估算。
   准备工具不保存路线，不能构成 route_task 成功；每回合最多两次实际准备，输入修正另计。

阶段性接线：`create_route_plan(use_prepared_candidates=true)` 使用服务端本轮地点骨架和已解析
坐标，沿用现有 Google/AMap 距离与质量检查，成功后保存准备快照。不会重复尝试旧 Strava 增强。
Strava 状态进入候选 warnings；混合骨架暂不送算路，也不声称最终路线采用 Strava。

### 材料协议与失败恢复修正（2026-09-18）

- 工具输入可省略 schema_version，服务端补齐；显式错误版本仍拒绝。
- 相同 query 的重复地点合并，统一 ID 引用、来源和必经标记；同 ID 同 query 也可合并，
  同 ID 不同地点拒绝。环线走廊末尾起点规范化，中途重复经过不删除，返回明确的拆分提示。
- 输入校验返回字段路径与修正提示，最多三次修正；与两次真实准备执行分开计数，总模型轮次上限八次。
- 尚无准备结果时提前阻止 prepared 创建；准备失败后不能改用直接创建绕过材料检查。
  连续执行失败耗尽预算时直接保留最后错误，不让后续 guard_rejected 覆盖 Provider 原因。
- 新增 locality 城市约束。提示模型保留用户市内要求；Google/AMap 保留城市字段，材料解析时核验。
  不将省/府视为城市，城市证据缺失也不能宣称满足范围；当前依赖模型正确提取 locality，
  不能将此检查描述为已完成所有自然语言地域识别或行政边界几何核验。
- 最新定向 Python 236 项、JavaScript 434 项通过；compileall / diff check 通过。
  两次真实京都请求仍受 Google Places 故障阻断，详情见真实对话验证文档；未证明距离质量。

### 2026-09-18：调用暂缓恢复与对话实时进度

- 搜索或材料准备之后，同一个模型响应中的后续工具返回 `route_requires_next_round` / `deferred`，不再写入业务失败记录。下一轮根据资料更改参数后成功，不会被旧的调度提示覆盖；真实 Guard 和 Provider 失败仍按原规则返回。
- 路线页面通过原 `/api/agent/chat` → `/api/chat` 请求的 `Accept: application/x-ndjson` 获取 `route_stream.v1` 事件：`progress`、`result`、`error`。普通 JSON 调用保持兼容。Node 只转发，Python 保留会话锁、幂等和最终结果的所有权。
- 进度来自 Route Agent 实际工具的开始/结束：搜索、材料准备、创建/修改路线；模型轮次显示“分析需求与规划下一步”。计时器只显示等待时间，不再按秒数推测处理阶段。已完成及失败步骤在本轮对话中保留，结束或页面销毁后停止计时并忽略迟到事件。
- 连接断开不视为取消或成功，不自动重放规划；后台已开始的同步操作仍可能完成。进度为当前请求的临时观察，不是新增持久化任务。

### 2026-09-18：材料校验恢复与独立进度区域

后续实际对话暴露另一种失败残留：`corridors[].point_ids` 只有一个点时材料校验失败，模型改正后材料准备和创建均成功，旧错误却仍被汇总为最终失败。现在仅当本任务后续材料准备确实返回 `prepared` 且写入当前准备上下文时，将此前该工具的 `route_materials_invalid` 记录标为 `recovered`。原始诊断保留，最终失败汇总忽略已恢复记录；未修正材料、Provider 错误及其他工具失败不受影响。不放宽线路至少两个点的校验。

规划进度改为输入框上方的独立状态区域，不再生成 Agent 聊天气泡。每个工具阶段仅保留最新状态，失败→重试→成功更新同一条目；最终结果和错误仍在对话中展示。替代上一节所述的进度气泡展示。

### 2026-09-18：候选简介与基于所选路线重新生成

- 卡片不再展示网页参考链接；检索证据仍在服务端保留。路线视图根据实际途经点生成简短介绍，“本地候选”名称替换为地点名称，避免额外模型调用及未经地图验证的景观/安全描述。

- 目标是重新验证三条不同候选；不足三条有效时如实返回，不复制凑数。新组创建失败不修改原计划；成功后页面展示新组。明确的 `update` 任务以及预览、反转、撤销等页面命令保持原操作语义。
