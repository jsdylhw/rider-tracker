# 爬楼做组分析

- `floor_climbing` 使用爬楼专项分析，不套用骑行功率或跑步配速。缺功率、GPS、踏频不是这类活动的缺陷，不建议为此增加功率设备。
- 当前用户约定默认上楼做组、下行乘电梯，按此解释恢复阶段，无需反复确认；这是场景假设，不是 FIT 证明的移动方式。用户另有说明时以其说明为准。
- 完整报告从初始 activity_features.stair_climbing 读取专项摘要、分区，从 effort_candidates.efforts 读取确定性做组结果；这些已由程序计算，不需要调用未开放的摘要或扫描工具。主对话通过 find_segments 的 interval/effort 获取估计做组。不能自己用分桶曲线另划组覆盖探测器。
- 逐组表格必须逐项使用候选的 start_s/end_s、max_hr_bpm、recovery_low_hr_bpm、recovery_duration_s，秒转分秒不改变数值；用 estimated_set_count 报告估计组数。心率分布必须列出工具提供的非零区间时长及占比。
- `stair_hr_cycles.v1` 用心率持续升降估计做组。起止和组数必须标明估计；心率有延迟，不能把峰值时刻当作上楼停止时刻。尾组或断点的 recovery_complete=false 表示恢复片段未完整观察，不是恢复能力差。
- 首个片段可能包含热身；没有动作记录或用户确认时，不能宣称估计组数就是实际组数。
- 按顺序比较每组心率峰值、起点心率、回落幅度、恢复片段时长。不能凭心率回落证明恢复充分，不能凭低谷抬升就判定疲劳；不把心率波动等同肌肉输出。
- 禁止将较大回落写成“恢复充分”，将峰值相近写成“出力一致”，或将设备心率阈值百分比写成已证实的“阈值区训练”。短时长不是缺少 NP/IF/TSS 的原因；本次运动缺少适用功率证据才是不计算的原因。
- 累计爬升可用不代表逐点海拔可用。全程平均爬升速率包括恢复，不是上楼速度；无逐点高度时不分摊各组爬升，不猜楼层或台阶。
- 心率分区优先使用 FIT session 的时长、边界和计算方法，不能叠加相同 lap 统计。Garmin TE 和 training_load_peak 原样说明，不把无氧 TE 较低理解为需要加量，不直接把设备阈值当作爬楼专项乳酸阈。
- 分区表只使用 stair_climbing.hr_zone_rows 的 range_label、duration_s、percentage，不自行命名 Z1/Z2/Z3 或有氧区/阈值区。边界未知就写未知。
- interpretation_limits 同时约束正文、小结、analysis_summary 和 strava_summary：没有可比历史时不评价“低总量/偏低/偏高/中等负荷”，load_label 可写“Garmin 负荷已记录，个人相对负荷未评估”。没有每组爬升/速度/功率时不评价“节奏稳定/出力稳定/效率提高”。只能比较具体心率或恢复片段数值。
- 尾组 recovery_complete=false 时恢复时长显示“未完整观察”，不要把 0 s 写成无需恢复。恢复回落幅度使用平滑峰值与平滑谷值之差，不能拿原始峰值另算后声称不一致。
- 报告面向用户，不输出“照抄工具值”、字段名或 recovery_complete=false 等实现细节；用“末组恢复未完整记录”。建议应聚焦下次记录/对比同条件下的组数和用时，不开固定加量处方。
- 跨组概括直接使用 effort_candidates.summary.comparisons：all_set_peak_hr_range_bpm 包含首组，不可擅自排除首组却写“各组”；恢复时长范围只覆盖完整片段。表格之后最多两项数值比较，不再自由推导最大/最小组次或趋势，避免把回落写成回升、把三组写成两组。
- analysis_summary.summary_label 只写“爬楼做组 · 估计 N 组”；不要新增“中等强度”等未经评估的标签。brief/strava_summary 同样只使用上述全组范围；48% 应写“占比最高”，不能写“超过一半/大多数”。恢复片段未完整观察时，不称为 0 秒恢复。
- 报告顺序：总时长/累计爬升 → 心率分布及 Garmin 负荷 → 估计逐组节奏 → 数据限制。数值从工具取用，29.4 分钟不能转述成 28 分钟；不输出无依据的固定恢复心率或加量处方。
